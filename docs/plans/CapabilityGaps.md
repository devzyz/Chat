# D：补齐能力与验收缺口

目标：优先完成认证和实例故障保护，让已实现的业务持续被验证，再补运行维护与性能证据。
总入口见 [仓库复核计划](RepositoryReview.md)，进度与已执行证据只见 [Status](../Status.md)。

| 批次 | 优先级 | 步骤与交付 | 验收条件 |
| --- | --- | --- | --- |
| D1 密码与请求 | P1 | 设计服务端密码哈希及旧账号迁移；统一邮箱/用户名/密码类型和长度校验；去除将可逆异或当成保护的依赖 | 直接 HTTP 非法请求被拒绝；新旧账号迁移、登录、改密有集成；数据库不再依赖可逆凭据验证；方案先说明客户端兼容影响 |
| D2 验证码 | P1 | 明确注册/重置用途、有效期、尝试预算和发送限流；安全随机生成；实现并发下原子校验/消费及失败语义 | 重放、跨用途、并发消费、过期及超预算均被拒绝；真实 Redis 和隔离 SMTP 有回归 |
| D3 Token | P1 | 定义过期、续期、登出/改密撤销与多端策略；同步 Status、Chat、Resource 校验及客户端错误处理 | 过期/撤销 Token 在各入口失效；重登/旧回调不跨账号；协议和 Redis 迁移可验证 |
| D4 传输保护 | P1 | 明确内外网边界和 HTTP/TCP/gRPC 保护方案；比较直接 TLS 与受控终止方式并落地配置 | 覆盖全部认证及消息链路；无效证书/身份拒绝；不能仅保护 Gate 而留下 Chat/Resource 明文 |
| D5 实例失效 | P1 | 为 Chat 实例建立有期限存活租约，Status 过滤失效候选；明确无可用实例和 Redis 不可用行为 | 强制终止实例后在约定期限内停止选服；正常恢复可重入；不让旧实例清理新实例状态 |
| D6 已知失败 | P1 | 独立复现 T10-4PROC-10 清理不完整和 E03-XMSG-08 伪造发送方断言失败，区分测试设施与业务根因后修复 | 原失败可复现、修复后所属回归通过、日志和清理结果完整；不得弱化断言 |
| D7 持续业务回归 | P1 | 盘点 resource-local 与 message-sync 入口；将已有资源/同步/回执关键场景接入合适的全量或定向 lane；逐步补真实 Status/Redis 组合 | CI 实际执行并保存报告；依赖失败非零；两个客户端的文本/附件/回执/重登流程有明确证据；快速 lane 不被无条件加重 |
| D8 资源治理 | P2 | 定义账号总配额、临时上传到期和孤立文件核对；提供 dry-run 清单、保留窗口和受限清理入口 | 不删除仍引用或可续传文件；并发发布/清理边界有测试；磁盘不足可诊断 |
| D9 性能与指标 | P2 | 建立固定数据与负载；测量吞吐、p95/p99、队列/连接池等待、内存、重连和大文件影响；重点观察 Chat 业务单线程及资源存储单线程 | 基线可重复，记录环境和误差；优化有前后数据；不牺牲顺序、幂等和关闭行为 |
| D10 恢复演练 | P2 | 定义 MySQL 与资源文件一致备份、恢复顺序、版本核验和失败处理；先对临时环境演练 | 恢复后消息/资源引用与字节一致；部分备份或错误版本明确失败；不操作个人数据库 |

D1/D2/D3 先确定相互兼容的认证合同，再分批实现；D4 可先完成部署边界设计。
D6 先复现，不能从一条失败记录直接推断漏洞。D7 复用已有测试设施；D9 先测量再决定分片/并行。
需要新增依赖、schema、协议或部署策略时，在对应批次设计和验证，不把本计划当作恢复本机依赖的授权。
