# C：降低工程维护成本

目标：减少同一变更需要同步的位置和低价值门禁成本，保留正确性、失败传播和可重复构建保障。
总入口见 [仓库复核计划](RepositoryReview.md)，进度只见 [Status](../Status.md)。

| 批次 | 优先级 | 步骤与交付 | 验收条件 |
| --- | --- | --- | --- |
| C1 注释规则 | P2 | 统计重复/模板注释及门禁维护成本；提出公开契约、所有权、线程、事务和复杂逻辑重点规则；政策调整时同步规范、检查器与正反例 | 简单转发/getter/短回调的豁免明确；重要契约仍被检查；不先绕过现行 MUST |
| C2 注册单一来源 | P2 | 把报告组、执行描述和数量读取收敛到一个注册源；保留独立的关键用例存在性及失败校验 | 新增一项测试无需同步多份手写总数；漏跑、重复、失败、超时、缺报告仍能阻断 |
| C3 脚本拆分 | P2 | 保留 windows-local.ps1 公开任务，将构建、注册、报告、规范职责拆成内部模块 | 原命令、退出码、路径与 DG-25 行为不变；所属脚本/构建合同回归通过 |
| C4 构建权威 | P3 | 记录 CMake 解析 vcxproj 的限制及真实维护事故；对统一源码描述或统一构建做小范围验证 | 只有可量化减少维护且双平台等价时才迁移；不复制第二套源码清单 |
| C5 工具链成本 | P3 | 测量快照大小、下载/恢复时间、缓存命中和构建失败原因；比较现方案与简化候选 | 保持已约定的每周升级/日常固定语义，或先明确变更该合同；无数据时不重写 |
| C6 测试文本耦合 | P2 | 将一般 YAML/脚本排版断言改为结构或行为检查；关键安全开关保留必要静态断言 | 等价格式调整不误报；错误配置和失败传播反例仍失败 |

先做 C2/C3/C6 的局部变化，再评估 C1/C4/C5。每批比较变更前后的使用步骤与维护位置，
不以减少测试数量作为收益，也不增加自定义任务框架或新的强制审批层。
