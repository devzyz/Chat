# E：客户端与产品收口

目标：让已实现能力具有明确数据权威、可理解的安装与使用方式，以及可重复的用户验收路径。
总入口见 [仓库复核计划](RepositoryReview.md)，实际进度只见 [Status](../Status.md)。

| 批次 | 优先级 | 步骤与交付 | 验收条件 |
| --- | --- | --- | --- |
| E1 消息数据所有权 | P2 | 追踪 SQLite/MessageService、ChatInfo 旧容器、Model 和 seedModelFromLegacyData；列出读写方，收敛事实来源并移除已无用途桥接 | 历史分页、ACK/回执先后、重启、账号切换和资源消息回归通过；展示缓存不另行创造消息事实 |
| E2 安装与目录 | P2 | 明确当前便携式可写安装目录合同；若支持标准安装，另设计数据路径和旧数据迁移 | 普通账号在受支持安装位置可运行；不可写时错误清楚；迁移不覆盖旧数据、不混入其他环境账号 |
| E3 功能边界 | P2 | 整理已支持/未支持能力，明确私聊、资源、回执及群聊状态；群聊若纳入范围，先修一群多成员数据模型 | UI 与使用说明不暗示未实现能力；未来群聊有迁移和权限测试，而非仅增加按钮 |
| E4 首次使用 | P2 | 在现有 README/构建与运行入口串联依赖、配置、迁移、启动、两账号验证和故障定位 | 新使用者可沿一条路径完成私聊/附件验证；命令引用权威入口，不复制第二套配置 |
| E5 发布资料 | P2 | 确定项目授权意图后补根 LICENSE、第三方声明、版本说明及安全反馈方式 | 发布资料与实际打包依赖一致；不擅自选择许可证或承诺未建立的反馈渠道 |
| E6 桌面验收 | P1 | 以已有生产服务组合验证双账号、文件选择器、头像裁剪、断线/重登、已读可见性和写入失败提示 | 自动控件/协议结果与人工桌面结果分开记录；有可复现步骤；与 D7 共享场景而不重复造测试设施 |

E1 依赖消息存储/回执回归保护；E4 可以先基于现有功能完成；E6 与 D7 联动。
新存储位置、群聊和许可证涉及产品选择，执行时先查既有约定，无法推断的选择再收集需求。
