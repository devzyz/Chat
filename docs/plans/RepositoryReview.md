# 仓库复核整改计划

制定日期：2026-09-26。依据本轮仓库静态复核；候选问题在执行前仍须按源码、调用和构建关系确认。
本文件定义目标、优先级和依赖；实际进度、下一步与验证边界只维护在 [Status](../Status.md)。

## 分类目标

| 类别 | 目标 | 执行计划 |
| --- | --- | --- |
| A 冗余清理 | 删除无生产用途的实现和跟踪产物，减少重复维护，保持现有行为 | [RedundancyCleanup](RedundancyCleanup.md) |
| B 过期与矛盾 | 当前文档与实现一致，历史证据不冒充当前状态 | [DocumentationConsistency](DocumentationConsistency.md) |
| C 过度工程化 | 降低日常变更成本，保留有实际故障保护价值的门禁 | [EngineeringSimplification](EngineeringSimplification.md) |
| D 能力缺口 | 补齐认证、实例失效、业务持续回归和运行维护能力 | [CapabilityGaps](CapabilityGaps.md) |
| E 客户端与产品收口 | 明确数据所有权、安装方式、支持范围和首次使用路径 | [ClientProductClosure](ClientProductClosure.md) |

## 执行顺序

1. 先执行 B：核实文档事实、区分历史与当前、统一权威入口。
2. A 的确定无用项可独立小批执行；优先推进 D 的认证、实例失效和已知失败复现。
3. 接入已有专项业务回归并完成 E 的使用与验收边界，再推进 C 的维护成本精简。
4. 性能工作先建立基线，再按结果调整 Chat 业务执行和资源存储执行方式。

P1 表示优先处理的安全、正确性或验收缺口；P2 表示维护与运行完善；P3 表示低收益候选。
优先级不是已复现故障等级；静态风险、已记录失败与本次执行结果必须区分。

## 共用边界

- 每批以一个可验证结果为范围，执行前检查已有修改；文档批次不隐含行为或规范政策变更。
- 保留 UUID 幂等、持久化 outbox、回执单调性、账号隔离、超时、有界队列和迁移校验。
- 不以精简为由合并服务、删除业务测试、改协议编号或重写 Git 历史。
- 不清理个人数据、依赖树、构建产物、工作树或 `tests/auto/`；依赖变更遵守 DG-25。
- 代码变更运行所属模块测试；数据或网络变更补集成；纯文档按比例检查事实、链接和 diff。
- 每批记录实际执行的验证，不把注册成功、替身测试或历史通过当成完整业务验收。
